# RPG Tournament

Пошаговый RPG-турнир на TypeScript с двумя режимами запуска: консольным и браузерным. Веб-интерфейс не просто отображает бой — он показывает, какие принципы ООП участвуют в каждом ходе: общий алгоритм атаки, динамический выбор реализации класса и стратегию текущей арены.

Демонстрация: https://j0es1ick.github.io/Game/

## Быстрый старт

Требования: Node.js 20+ и npm 9+.

```bash
npm install
npm run dev
```

Vite откроет приложение по адресу `http://localhost:3000/Game/`.

Консольная версия:

```bash
npm run dev_con
```

Проверки проекта:

```bash
npm run typecheck
npm test
npm run build
npm run build:console
```

## Архитектурная идея

В проекте намеренно оставлены только те паттерны, которые решают реальную задачу.

### Simple Factory

`PlayerFactory` — единственная фабрика персонажей. Она принимает описание героя и возвращает нужный подкласс: `Knight`, `Archer` или `Wizard`.

Отдельные `KnightFabric`, `ArcherFabric` и `WizardFabric` удалены: они не скрывали сложного создания и лишь дублировали вызовы конструкторов.

Навыки и оружие теперь находятся в каталогах. Это конфигурационные данные, поэтому изображать их отдельными фабриками нет необходимости.

### Template Method

`Player.attack()` определяет общий скелет атаки:

```text
активные бонусы
  → классовый модификатор урона
  → стратегия арены
  → получение урона противником
```

Подклассы меняют отдельные шаги, не копируя весь алгоритм.

### Polymorphism

Все герои работают через контракт `Player`, но одинаковый вызов приводит к разному поведению:

| Класс | Переопределённый метод | Поведение |
| --- | --- | --- |
| `Knight` | `takeDamage()` | тяжёлая броня поглощает 22% урона |
| `Archer` | `modifyOutgoingDamage()` | каждая третья атака получает множитель ×1.5 |
| `Wizard` | `useSkill()` | успешный навык восстанавливает 6 HP |

Последний динамический вызов сохраняется как `DispatchTrace` и показывается в Live Inspector веб-интерфейса.

### Strategy

Арены реализуют единый контракт `IArena` и взаимозаменяемо модифицируют урон:

| Арена | Урон | Награда |
| --- | ---: | ---: |
| Учебный двор | ×0.90 | 25 XP |
| Вулканический кратер | ×1.15 | 40 XP |
| Древние руины | ×1.00 | 55 XP |

`ArenaPool` хранит доступные стратегии и выбирает одну для нового боя. Он не называется фабрикой, потому что не строит сложные объекты.

## Турнирный runtime

`Game` является единственным владельцем состояния турнира:

- формирует раунды и пары;
- обрабатывает проход без соперника;
- запускает пошаговый бой;
- начисляет опыт;
- хранит выбывших и победителя;
- возвращает `TurnReport` для каждого шага.

Раньше браузерный слой самостоятельно повторял эту логику. Теперь `ui.ts` отвечает только за ввод, рендеринг и скорость автовоспроизведения.

`TurnReport` содержит не только результат удара, но и список архитектурных событий:

- `Template Method` — запуск `Player.attack()`;
- `Strategy` — вызов `Arena.modifyDamage()`;
- `Polymorphism` — конкретный переопределённый метод класса.

## Структура

```text
src/
├── abstract/Player.ts        # базовый класс и template method
├── arenas/                   # стратегии арен и ArenaPool
├── catalogs/                 # конфигурация навыков и оружия
├── classes/                  # Knight, Archer, Wizard
├── factories/PlayerFactory  # единственная фабрика доменных объектов
├── gameplay/Game.ts          # бой и состояние турнира
├── utils/                    # ввод, вывод и случайные значения
└── web/                      # SPA-интерфейс и Live Inspector

tests/
├── PlayerClasses.spec.ts     # реальный полиморфизм
├── PlayerFactory.spec.ts
├── ArenaPool.spec.ts
├── Catalogs.spec.ts
├── Game.spec.ts
└── ...
```

## Docker

Docker-образ запускает консольную версию:

```bash
docker build -t oop-arena .
docker run -it oop-arena
```

SPA публикуется отдельно через workflow GitHub Pages из каталога `dist`.
